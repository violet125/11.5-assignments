# 数据字典

字段口径以本文为准。台账真实数据须由业务及工程人员建设和核实，开源软件不能替代真实数据采集。

## 一、需求字段取值状态

需求字段的"空白"有三种不同业务语义，不可混为一谈。系统用 `state` 表达：

| state | 含义 | 交接影响 |
| --- | --- | --- |
| `specified` | 已明确，有数值或枚举值 | 参与硬条件匹配 |
| `unknown` | 客户提到过该维度但没给准数 | 必填时阻断交接，必须补问 |
| `not_requested` | 本次访谈未涉及该维度 | 必填时仍需客户确认无此要求 |
| `none_confirmed` | 客户明确表示不需要，已确认 | 必填时记为提示项，不阻断 |

`not_requested` 与 `none_confirmed` 的差别是本项目的核心：`not_requested` 是"没聊到"，交接前仍要向客户确认；`none_confirmed` 是"客户说了不需要"，已有依据。

## 二、需求与房源字段

| 字段 | 名称 | 单位 | 比较方向 | 备注 |
| --- | --- | --- | --- | --- |
| `area` | 最小面积 | ㎡ | 下限（房源 ≥ 需求） | 面积上限人工核实 |
| `rent` | 最高月单价 | 元/㎡/月 | 上限（房源 ≤ 需求） | 年租金、总租金不得折算冒充月单价 |
| `power` | 最低供电容量 | kVA | 下限 | 设备功率 kW 不可直接替代 kVA |
| `load` | 最低楼面承重 | kg/㎡ | 下限 | 需区分楼面承重与集中荷载 |
| `height` | 最低净高 | 米 | 下限 | 梁下或装修面以上净尺寸，不得用层高替代 |
| `layer_height` | 最低层高 | 米 | 下限 | 楼层高度，与净高是两个独立字段 |
| `redundancy` | 配电冗余 | 枚举 | 等级（单路 < 双路 < N+1） | 需工程确认 |

比较方向说明：
- 下限字段：房源实际值 ≥ 需求值才算满足。
- 上限字段：房源实际值 ≤ 需求值才算满足。
- 枚举等级字段：需求"双路"可由房源"双路"或"N+1"满足；需求"N+1"只能由"N+1"满足。

## 三、房源台账字段

除上表参数外，每条房源还需溯源信息：

| 字段 | 名称 | 说明 |
| --- | --- | --- |
| `name` | 房源名称 | 必填，同一台账内不可重复 |
| `source` | 资料来源 | 图纸编号、勘察报告等 |
| `verifier` | 核实人 | 实际核实参数的工程或业务负责人 |
| `verified_at` | 核实日期 | YYYY-MM-DD |
| `version` | 数据版本 | 如 v1、v2 |

可选描述字段：`park`（园区）、`building`（楼栋）、`floor`（楼层）、`usable_area`（可用面积）、`delivery_date`（交付日期）、`notes`（备注）。

### 报价参数（不参与匹配）

台账可另填六个仅用于报价的参数，随报价单带出，不参与硬条件匹配：

| 字段 | 名称 | 单位/取值 | 备注 |
| --- | --- | --- | --- |
| `efficiency_ratio` | 得房率 | %（1~100） | 计租面积 = 登记面积 × 得房率；缺省按 100% 并提示 |
| `property_fee` | 物业费 | 元/㎡/月（0~1000） | 缺省按 0 计入三年成本并提示需补登记 |
| `delivery_status` | 交付标准 | 毛坯 / L1 / L2 / L3 | 决定装修单价查表档位 |
| `net_height` | 净高 | 米（0.1~30） | 报价参考，不参与匹配（匹配用需求侧 `height`） |
| `power_redundancy` | 供电冗余 | 单路 / 双路 / 双路+应急 / N+1 | 报价参考，不参与匹配 |
| `hvac_overtime_fee` | 空调加时费 | 元/㎡/月（0~1000） | 随报价单展示 |

溯源信息不完整的房源不会被判为"已填条件满足"，只作为待核实素材。原因是：未经核实的参数即使数值正确，也无法支撑交付承诺。

## 四、单位口径红线

以下情况一律拒绝入库或降级处理，不做自动换算：

| 情形 | 处理 |
| --- | --- |
| 房源参数填了带单位文本（如 `500㎡`） | 拒绝导入，提示只填数值 |
| 设备功率 kW 填入 `power` | 拒绝导入 |
| kW 出现在 `power` 字段的原文证据中 | 降级为"未知待补"并阻断交接 |
| 层高出现在 `height` 字段的原文证据中 | 阻断交接，要求确认是梁下净高还是楼层层高 |
| 年租金、总租金出现在 `rent` 字段证据中 | 降级为"未知待补" |
| 只提供层高 | 净高保持"未知待补"，不按层高推定 |

## 五、未知值写法

房源参数未知时填 `null`，不能填 `0`。填 `0` 会被判为非法值（参数必须大于零）。

## 六、报价单字段口径

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| `quote_no` | 报价编号 | `RJ-{YYYYMM}-{序号}`，全局递增 |
| `quote_version` | 版本号 | 同一需求卡 + 房源第 N 次生成 |
| `round` | 轮次 | 首次报价 / 修订报价（version > 1 时必须填修订原因） |
| `revision_reason` | 修订原因 | version > 1 时必填，≥4 字 |
| `status` | 状态 | draft / issued / voided；升版时旧版自动 voided |
| `valid_until` | 有效期止 | 生成时间 + `validity_days`（默认 15 天）的 Unix 时间戳 |
| `approved_by` / `approved_at` | 授权审批 | 超授权报价须管理员审批后才能发出 |

### 三年总占用成本构成

| 字段 | 含义 | 口径 |
| --- | --- | --- |
| `rentable_area` | 计租面积 | 登记面积 × 得房率；缺得房率按 100% |
| `rent_3y` | 三年租金 | 月单价 × 计租面积 × 12 × (1 + (1+递增) + (1+递增)²) |
| `property_3y` | 三年物业费 | 物业费 × 计租面积 × 36 |
| `renovation_input` | 装修投入 | 装修单价 × 计租面积；单价按交付标准查表（见下）或人工覆盖 |
| `subsidies_total` | 补贴合计 | 装修补贴 + 搬迁补贴 |
| `total_3y` | 三年总占用成本 | rent_3y + property_3y + renovation_input − subsidies_total |
| `ledger_rent` / `discount_pct` | 台账价与折扣 | 折扣 = (台账租 − 报价) ÷ 台账租 × 100；台账无租金时不计折扣 |

装修单价查表（元/㎡，取区间中值，属行业参照，需园区确认；配置于 `quotation.renovation_cost_per_sqm`）：

| 交付标准 | 区间 | 取中值 |
| --- | --- | --- |
| L1 | 300–600 | 450 |
| L2 | 100–300 | 200 |
| L3（近零/精装） | 0–30 | 15 |
| 毛坯 | 300–800 | 550 |

## 七、退回原因枚举

驳回需求卡时 `reason_code` 必须取以下 12 个代码之一，理由文本作附注；复核历史同时展示代码与文案。

| 代码 | 文案 |
| --- | --- |
| HW_MISSING | 硬件条件缺失（层高/承重/配电等未登记） |
| HW_MISMATCH | 硬件条件不匹配 |
| HW_UNVERIFIED | 硬件条件未核实 |
| CAPACITY_MISSING | 容量参数缺失（供电容量等） |
| AREA_MISMATCH | 面积不匹配 |
| DELIVERY_UNCONFIRMED | 交付条件未确认 |
| PRICE_OVER_LIMIT | 价格超限 |
| INCENTIVE_ABOVE_AUTH | 让利超授权 |
| VERSION_CONFLICT | 版本冲突 |
| OLD_MATERIAL_SENT | 送错材料/旧版材料 |
| MISSING_BASIS | 缺少依据或溯源 |
| SYSTEM_UNAVAILABLE | 系统不可用（人工通道） |
